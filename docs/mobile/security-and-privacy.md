# Mobile Connection Security

AxiOwl separates the host daemon, the mobile client, the relay, and provider runtimes so each has a narrow role.

## Device Approval

Pairing starts from a fresh offer generated by the host daemon. The phone presents its stable client identity through that offer, and the desktop user approves it during the pairing window.

Paired devices are stored individually. Removing one device does not require replacing every other paired phone.

## Encrypted Relay Traffic

The relay connection is end-to-end encrypted between the mobile client and host daemon. The relay routes frames using connection identifiers but does not need the keys that open provider prompts or timelines.

## Provider Credentials Stay On The Host

The mobile app controls an agent through the daemon. It does not receive the provider's account token. Provider processes continue to run under the host user's account and local provider configuration.

## Direct Connections

Direct mode places network reachability under the operator's control. Use a private network, VPN, or properly secured host endpoint and configure transport security and daemon authentication for the route.

## Metadata

Connection services can observe operational metadata such as connection timing, route identifiers, availability, and encrypted frame sizes. The host and mobile app can see the projects, sessions, and timeline content required for the user experience.

## Reset And Revocation

The desktop can reject a pending device, remove a paired device, or reset paired-device state. A removed device must pair and receive approval again before it can open a daemon session.
