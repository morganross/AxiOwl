# Choose The Right AxiOwl Workflow

## One Local Provider Session

When all work happens in one provider conversation, use the provider directly. Add AxiOwl when that session should collaborate with another provider, agent, node, or mobile client.

## Several Local AI Tools

Use provider packages and the local registry for cross-provider delegation, review, and synthesis.

## A Phone Controlling Desktop Agents

Install an AxiOwl daemon, pair the phone, and use the encrypted relay or a direct daemon route.

## External Agent Services

Use A2A when the destination publishes an Agent Card and task interface.

## Operator-Managed Nodes

Use direct A2A or A2A-over-SSH when you manage both installations and want explicit node-to-node agent access.

```text
same-computer provider session -> local provider package
paired mobile app              -> relay or direct daemon connection
external agent service         -> A2A
managed AxiOwl node             -> A2A or A2A-over-SSH
```

Read [Choosing A Transport](../how-it-works/choosing-a-transport.md).
